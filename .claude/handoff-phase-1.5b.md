# Hand-off — Phase 1.5b (Payload Bootstrap)

Payload 3.84 is wired into `apps/silbe/` via `@payloadcms/next` with a multi-root App Router layout: `app/(frontend)/` keeps the brand storefront (Header/Footer/fonts moved here intact), and `app/(payload)/` exposes the admin (`/admin`), REST (`/api/[...slug]`), GraphQL (`/api/graphql`), and GraphQL Playground (`/api/graphql-playground`) under Payload's RootLayout. The config (`payload.config.ts`) registers a minimal Pages collection (title + slug + body, public read), a `users` auth collection, the postgres adapter pointing at `DATABASE_URI` from `.env.local`, the lexical editor, and Sharp; `next.config.ts` is wrapped with `withPayload`, and `tsconfig.json` adds the `@payload-config` alias. `pnpm build` is clean (5 routes register), `pnpm dev` boots cleanly and `/admin` returned `200 OK` with the Postgres schema pulled. **Seeding `editorial-letter-homepage` is the one thing that didn't auto-run**: under Node 25.9 the `payload` package's default-import of `@next/env` evaluates to `undefined`, so the seed script (`scripts/seed-pages.ts`) and the `payload generate:importmap` CLI both fail at module-load time with `Cannot destructure 'loadEnvConfig' of undefined`. The script is committed for when Node 22 LTS or a Payload interop fix is in play; in the meantime, create the first admin user on the first visit to `/admin`, then add the Page via the admin UI (`/admin/collections/pages/create`, slug `editorial-letter-homepage`). The empty `app/(payload)/admin/importMap.js` stub is regenerated automatically by the dev server's HMR when custom field components are introduced.
